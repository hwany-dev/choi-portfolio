# Eunji Choi 사이트 관리 가이드

사이트의 글과 사진은 전부 **Firebase 콘솔**에서 바꿉니다.
코드를 고치거나 다시 배포할 필요는 없습니다. **저장하고 사이트를 새로고침하면 바로 반영됩니다.**

- 사이트 주소: https://choi-portfolio-98f6a.web.app
- Firebase 콘솔: https://console.firebase.google.com/project/choi-portfolio-98f6a
  - 글·정보 → 왼쪽 메뉴 **Firestore Database**
  - 사진 → 왼쪽 메뉴 **Storage**
- 로그인이 안 되면 사이트 관리자에게 프로젝트 초대를 요청하세요 (Google 계정 필요).

> 📷 스크린샷: Firebase 콘솔 첫 화면, 왼쪽 메뉴의 Firestore Database / Storage 위치

---

## 1. 무엇이 어디에 있나

| 콘솔 위치 | 사이트에서 바뀌는 곳 |
|---|---|
| Firestore → `settings` → `site` 문서 | 홈 문구, 프로필, 인스타그램 링크 |
| Firestore → `works` 컬렉션 (프로젝트 1개 = 문서 1개) | WORKS 그리드, PROJECT LIST, 프로젝트 상세 페이지 |
| Storage → `works/문서ID/` 폴더 | 그 프로젝트의 사진 |
| Storage → `profile/profile.jpg` | 프로필 사진 |

프로젝트 하나를 추가하면 WORKS·PROJECT LIST·상세 페이지에 **한 번에** 반영됩니다.

---

## 2. 새 프로젝트 추가하기

### 2-1. 문서 ID 정하기

형식: **`카테고리-연도-번호`** (영어 소문자, 띄어쓰기 없음, 번호는 두 자리)

| 카테고리 | 문서 ID 예시 |
|---|---|
| BTL | `btl-2026-04` |
| EXHIBITION | `exhibition-2026-01` |
| SPACE | `space-2026-01` |
| POP UP | `popup-2026-01` (띄어쓰기 빼고) |
| PERFORMANCE | `performance-2026-02` |
| COMMUNITY | `community-2026-01` |

같은 카테고리·같은 연도에 이미 `-01`이 있으면 `-02`처럼 다음 번호를 씁니다.
**문서 ID는 사이트 주소가 됩니다** (`/works/exhibition-2026-01`). 한 번 정하면 바꾸지 마세요.

### 2-2. Firestore에 문서 만들기

1. Firestore Database → `works` 컬렉션 클릭
2. **문서 추가** 클릭
3. **문서 ID** 칸에 2-1에서 정한 ID 입력 (자동 ID 쓰지 않기)
4. 아래 표대로 필드를 하나씩 추가 → **저장**

> 📷 스크린샷: works 컬렉션 → 문서 추가 창 (문서 ID 칸, 필드 이름·유형·값 칸)

| 필드 이름 | 유형 | 필수 | 예시 | 사이트에서 |
|---|---|:-:|---|---|
| `category` | string | ✔ | `EXHIBITION` | 필터 탭, 리스트 |
| `year` | **number** | ✔ | `2026` | 정렬, 연도 묶음 |
| `title` | string | ✔ | `Google AI for Business 2026` | 그리드·리스트·상세 |
| `detailTitle` | string | | | 상세 페이지 큰 제목 (비우면 title) |
| `client` | string | | `Google Korea` | 상세 정보 |
| `date` | string | | `2026.07.14.-07.16.` | 상세 정보 (형식 자유) |
| `location` | string | | `서울신라호텔` | 상세 정보 |
| `details` | string | | 긴 설명 | 상세 정보 |
| `partners` | string | | | 상세 정보 |
| `workRange` | string | | | 상세 정보 |
| `order` | **number** | | `10` | 같은 연도 안 순서 (작을수록 앞) |
| `published` | **boolean** | | `true` | `false`면 사이트에서 숨김 |

- **필드 이름은 표와 똑같이** (대소문자까지) 입력하세요. `detailtitle` ✗ → `detailTitle` ✓
- **카테고리 값**: `BTL` `EXHIBITION` `SPACE` `POP UP` `PERFORMANCE` `COMMUNITY`.
  새 카테고리를 입력하면 WORKS 필터 탭 맨 뒤에 자동으로 생깁니다. 같은 카테고리는 항상 같은 철자로.
- **비워둘 항목**은 필드를 만들지 않거나 빈칸으로 두면 됩니다. 사이트에서 그 줄은 자동으로 숨겨집니다.
- **줄바꿈**: 입력칸에서 Enter로 줄이 안 바뀌면 `\n` 이라고 쓰세요. 사이트에서 줄바꿈으로 보입니다.
  예: `첫째 줄\n둘째 줄`
- `published` 필드는 없어도 됩니다 (없으면 보이는 상태).

### 2-3. 사진 올리기

1. Storage → `works` 폴더로 이동
2. **폴더 만들기** → 이름을 **문서 ID와 똑같이** (`exhibition-2026-01`)
3. 그 폴더 안에 **파일 업로드**

> 📷 스크린샷: Storage → works → 폴더 만들기 / 파일 업로드 버튼

파일 이름 규칙:

| 파일 이름 | 쓰이는 곳 |
|---|---|
| `00.jpg` | **대표 사진** — WORKS 썸네일 + 상세 페이지 맨 위 큰 사진 |
| `01.jpg`, `02.jpg`, `03.jpg` … | 상세 페이지 사진 (이 순서대로, 개수 제한 없음) |

- 이름 순서대로 정렬해서 **첫 번째 파일이 대표**가 됩니다. 번호는 꼭 두 자리(`01`, `02` … `10`).
- 가로 사진 두 장이 연달아 있으면 상세 페이지에서 나란히 놓입니다.
- 사진을 아직 안 올리면 회색 박스에 제목이 보입니다 (고장 아님).

## 3. 수정 · 숨기기 · 삭제

- **수정**: 문서를 열고 바꿀 필드의 값을 클릭 → 수정 → 업데이트.
- **숨기기**: `published` 필드를 `false`로 (유형 boolean). 다시 보이게 하려면 `true`.
  필드가 없으면 **필드 추가** → 이름 `published`, 유형 boolean, 값 false.
- **완전히 삭제**: 문서 삭제 + Storage의 같은 이름 폴더 사진 삭제.
  나중에 다시 쓸 수도 있으면 삭제 대신 숨기기를 권장합니다.

---

## 4. 순서 바꾸기

- **최신 연도가 먼저**, 같은 연도 안에서는 **`order`가 작은 것이 먼저** 나옵니다.
- 기존 프로젝트는 10 단위(0, 10, 20 …)로 되어 있어서, 사이에 넣고 싶으면 `15`처럼 중간 값을 쓰면 됩니다.
- 상세 페이지의 `← Prev` / `Next →`도 같은 순서를 따릅니다.

---

## 5. 사진 교체 · 추가

- **대표 사진 교체**: 폴더의 `00.jpg`를 삭제하고 새 사진을 `00.jpg` 이름으로 업로드.
- **상세 사진 추가**: 다음 번호로 업로드 (예: 마지막이 `04.jpg`면 `05.jpg`).
- **순서 바꾸기**: 파일 이름 번호를 바꿔서 다시 올리면 됩니다.
- 바뀐 사진이 안 보이면 **강력 새로고침**: Windows `Ctrl + Shift + R`, Mac `Cmd + Shift + R`.
  사이트를 오래 열어둔 창은 사진 목록을 최대 30분 동안 기억하니, 새 창에서 확인하는 게 가장 확실합니다.

---

## 6. 홈 · 프로필 · 인스타그램 바꾸기

Firestore → `settings` → `site` 문서에서 값만 바꾸면 됩니다.

| 필드 | 사이트에서 |
|---|---|
| `siteTitle` | 홈 맨 위와 페이지 맨 아래의 큰 이름 (자동으로 대문자 표시) |
| `heroTagline` | 홈 왼쪽 작은 두 줄 (비우면 숨김). 줄바꿈은 `\n` |
| `heroCopy` | 홈 오른쪽 큰 문구 3~4줄. 줄바꿈은 `\n` |
| `profileName` | 프로필 이름 |
| `profileRole` | 프로필 직함 |
| `profileBio` | 프로필 소개글. 문단 나누기는 `\n` |
| `profileImage` | `profile/profile.jpg` 그대로 두기 (사진은 Storage에서 교체) |
| `instagramUrl` | 상단 메뉴의 `Instagram ↗` 링크 |
| `email` | 현재 사이트에 표시되지 않음 |

- **프로필 사진 교체**: Storage → `profile` 폴더 → 기존 `profile.jpg` 삭제 → 새 사진을 `profile.jpg` 이름으로 업로드.
  사이트에서 자동으로 흑백으로 보입니다.

---

## 7. 사진 권장 사양

- 형식: **jpg 또는 webp** (png, avif, gif도 가능)
- 크기: **긴 변 2000~2400px, 한 장 1MB 이하** — 사이트가 빨리 열립니다
- **아이폰 HEIC 사진은 안 보입니다.** jpg로 바꿔서 올리세요.
  (아이폰 설정 → 카메라 → 포맷 → **높은 호환성**으로 바꾸면 이후 사진은 jpg로 찍힙니다)
- 파일 이름은 영어·숫자로 (`00.jpg`)

---

## 8. 하지 말아야 할 것

- **문서 ID 바꾸기** — 프로젝트 주소가 바뀌고, Storage 폴더도 새 이름으로 만들어 사진을 다시 올려야 합니다.
- **필드 이름 오타** — 대소문자까지 표와 같게.
- **`year`, `order`를 string으로 넣기** — 유형을 꼭 **number**로.
- **`settings`, `works` 이름 바꾸기, 다른 컬렉션 삭제.**

필수 필드(`category`, `year`, `title`)가 빠진 프로젝트는 그 프로젝트만 사이트에서 빠지고, 나머지는 정상으로 보입니다.

---

## 9. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 프로젝트가 안 보여요 | `published`가 false인지 / `category`·`year`·`title`이 다 있는지 / 필드 이름 철자 |
| 사진이 안 보여요 | Storage 폴더 이름이 문서 ID와 정확히 같은지 / HEIC 파일인지 / 강력 새로고침 |
| 순서가 이상해요 | `year`·`order` 유형이 number인지 |
| 줄바꿈이 안 돼요 | 입력칸에 `\n`을 썼는지 |

그래도 안 되면 **문서 ID와 화면 캡처**를 사이트 관리자에게 보내주세요.
